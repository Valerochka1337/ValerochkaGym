# ValerochkaGym

Android-приложение для ведения силовых тренировок: планы тренировок, библиотека упражнений с
разметкой мышц, активная тренировка с таймером отдыха, календарь тренировок с планированием,
аналитика нагрузки и прогресса, выгрузка результатов в Google Sheets и Google Calendar.

- Пакет: `com.valerochka1337.valerochkagym`
- minSdk 36, Kotlin + Jetpack Compose (Material 3), Hilt, Room, DataStore.

## Порядок упражнений

В редакторе программы и в текущей тренировке порядок меняется перетаскиванием за grip справа от
названия упражнения. Grip — единственная зона начала переноса: поля, подходы и прокрутка списка
остаются независимыми от жеста. Во время переноса список автоматически прокручивается у края;
TalkBack предлагает для каждой карточки действия **«Переместить выше»** и **«Переместить ниже»**.

Это два разных порядка. В редакторе после **«Сохранить»** меняется порядок упражнений программы.
В уже начатой тренировке перестановка сохраняется только в текущей сессии и не переписывает
исходную программу. После завершения предложение **«Обновить программу?»** при подтверждении
сможет применить фактически выполненный порядок вместе с подходами.

## Календарь и расписание

Вкладка **Календарь** заменяет прежнюю «Историю» и совмещает историю (что сделано) и
планирование (что запланировано). Месячная сетка Пн–Вс листается стрелками и свайпом; в каждом дне:

- прошлые дни — **залитая точка**, если в этот день была завершённая тренировка;
- сегодня и будущее — **контурная точка**, если день запланирован.

Тап по дню открывает нижнюю шторку. Из неё можно открыть детали завершённой тренировки,
начать/удалить запланированную или, для пустого будущего дня, нажать **«Запланировать»**.

Есть два вида запланированных тренировок:

| Вид | Что это | Хранение | Google Calendar | Удаление |
|---|---|---|---|---|
| **Ad-hoc** | тап по дню → программа + время | `ScheduledWorkoutEntity` (Room) | одно событие | по одной |
| **Расписание** | недельный шаблон (7 дней) | `WeeklySchedule` в DataStore | одно RRULE-событие на день недели (`FREQ=WEEKLY`, бессрочно) | вся серия целиком |

Редактор расписания открывается иконкой в шапке календаря. **«Сохранить»** применяет шаблон с
заменой серии (старые события удаляются, создаются новые), **«Очистить расписание»** удаляет
всю серию и шаблон. Для планирования нужен выданный доступ к Google Calendar (см. настройку ниже);
повторяющиеся события создаются с явной таймзоной устройства — этого требует Google Calendar API.

## Мышцы упражнений

Упражнение описывается не одной группой мышц, а **картой вовлечения**: жим лёжа — это грудь 100%,
трицепс 65%, передняя дельта 60% и пресс 10%. Крупная категория (`MuscleGroup`) осталась для
фильтров библиотеки и колонки `muscle_group` в выгрузке, а карта (`Muscle` × доля 0–100%) питает
всю аналитику.

| Что | Где |
|---|---|
| 18 мышц второго уровня | `data/db/entity/Muscle.kt` |
| Таблица `exercise_muscles` | `data/db/entity/ExerciseMuscleEntity.kt`, миграция `MIGRATION_2_3` |
| Карты встроенного каталога | `data/db/SeedExerciseMuscles.kt` (68 упражнений) |
| Фоллбэк по группе мышц | `data/db/MuscleDefaults.kt` |

Числа собраны по ЭМГ-исследованиям и анатомическим таблицам (Coratella, Saeterbakken, Youdas,
Martín-Fuentes, ExRx, обзоры Schoenfeld) и приведены к общей шкале: **100** — целевая мышца,
**55–85** — сильный синергист, **25–50** — заметное участие, **10–20** — стабилизатор.

Карту можно править: тап по упражнению в библиотеке открывает редактор с **интерактивной моделью
тела** — нажатие на мышцу добавляет её, ползунок задаёт долю 0–100%. Тот же редактор создаёт своё
упражнение (кнопка «+»), и тогда крупная группа выводится автоматически из самой вовлечённой мышцы.
У встроенных упражнений название не меняется — по нему карта ищется в каталоге, а импорт из Sheets
сопоставляет строки.

Упражнения без карты (созданные раньше, приехавшие импортом) получают типичную для своей группы
разметку при следующем открытии базы — досевом в `ExerciseMuscleSeeder`.

## Анализы

Вкладка **Анализы** отвечает на два вопроса: «чего не хватает в плане» и «работает ли план».
Переключатель периода (4 недели / 12 недель / год / всё) стоит один раз над всеми карточками —
все графики показывают один и тот же срез.

| Карточка | Что показывает | На чём основана |
|---|---|---|
| Итоги периода | тренировок, рабочих подходов, тоннаж, средняя длительность, серия недель, кардио в МЕТ-минутах | норма ВОЗ 500–1000 МЕТ-мин/нед, уравнения ACSM для дорожки |
| Карта нагрузки | две фигуры рядом — спереди и сзади, залитые по недельному объёму мышцы; тап — подробности | ступени = зоны MEV / MAV / MRV |
| Объём по мышцам | bullet-график: факт против ориентиров, отсортировано по дефициту | 10–20 подходов/нед (Schoenfeld 2017, Baz-Valle 2022, Pelland 2026) + landmarks Israetel/RP |
| Частота и пауза | дней с последней работы по каждой мышце, метки на 2/4/7 днях | ≥ 2 раза в неделю на мышцу (Schoenfeld/Krieger 2016) |
| Недельный объём | подходы или тоннаж по неделям + средняя за закрытые недели | — |
| Скачок нагрузки | подходы за 7 дней к средней неделе за 28 дней | ACWR: коридор 0.8–1.3, > 1.5 — риск (Gabbett) |
| Баланс объёма | жим/тяга, перёд/зад, верх/низ, бицепс бедра/квадрицепс на логарифмической шкале | цель 1:1 и коридор ±25%; H:Q по объёму не ниже 0.5 |
| Прогресс по упражнению | тренд оценки одноповторного максимума + вердикт (растёт / плато / снижается) и силовая кривая «вес × повторения» | формула Эпли до 12 повторений; порог заметности max(1.25 кг, 1%) |
| Рекорды | лучший расчётный максимум по каждому упражнению за всю историю | — |

Ключевые соглашения расчёта (все — в `domain/analysis/AnalyticsEngine.kt`):

- **рабочий подход** — выполненный подход силового упражнения или упражнения на время; разминка
  отсекается эвристикой «легче 60% от лучшего подхода этого упражнения в этой тренировке»;
- **эффективный подход мышцы** — ступенчатый вес по доле вовлечения (прямая работа 1.0, косвенная
  0.5, стабилизация 0): именно ступени, а не `доля / 100`, валидированы мета-анализом объёма,
  иначе стабилизаторы набирают несуществующий объём;
- недельные величины — **средние за неделю окна**, поэтому 4 недели и год сравнимы между собой и
  с ориентирами;
- в аналитику попадают только **завершённые** тренировки: объём идущей ещё меняется.

## Настройка Google-интеграции

Чтобы работали вход через Google и выгрузка в Google Sheets/Calendar, нужно создать проект
в Google Cloud и вставить в приложение свой OAuth Web client ID. Всё делается один раз.

### 1. Создать проект

1. Откройте [Google Cloud Console](https://console.cloud.google.com/).
2. Вверху выберите **Select a project → New Project**, задайте имя (например, `ValerochkaGym`)
   и создайте проект.

### 2. Включить нужные API

В меню **APIs & Services → Library** включите два API:

- **Google Sheets API**
- **Google Calendar API**

Для каждого нажмите **Enable**.

### 3. Настроить OAuth consent screen

1. Перейдите в **APIs & Services → OAuth consent screen**.
2. Тип пользователей — **External**, нажмите **Create**.
3. Заполните обязательные поля (название приложения, email поддержки, email разработчика).
4. На шаге **Scopes** можно ничего не добавлять — приложение запрашивает доступ во время работы.
5. На шаге **Test users** добавьте свой Google-аккаунт (иначе вход будет заблокирован, пока
   приложение не прошло верификацию).

### 4. Создать OAuth client ID для Web application

1. Перейдите в **APIs & Services → Credentials → Create Credentials → OAuth client ID**.
2. Тип приложения — **Web application**, задайте имя (например, `ValerochkaGym Web`).
3. Нажмите **Create** и скопируйте **Client ID** (вида `1234567890-xxxx.apps.googleusercontent.com`).
4. Вставьте его в `app/src/main/res/values/strings.xml` в строку `google_web_client_id`
   (в репозитории уже лежит ID проекта владельца — для своего проекта замените на свой).

> Именно **Web** client ID передаётся в `serverClientId` библиотеки входа — это не опечатка,
> так работает Credential Manager / Google Identity.

### 5. Создать OAuth client ID для Android

1. Снова **Create Credentials → OAuth client ID**, тип приложения — **Android**.
2. **Package name**: `com.valerochka1337.valerochkagym`.
3. **SHA-1**: получите отпечаток командой из корня проекта:

   ```bash
   ./gradlew signingReport
   ```

   Скопируйте значение `SHA1` для нужного варианта (debug для отладочной сборки).
4. Нажмите **Create**. Отдельно в приложение этот ID вставлять не нужно — Google связывает
   Android-приложение с проектом по package name и SHA-1.

### 6. Где взять ID таблицы

ID таблицы Google Sheets — это часть её ссылки:

```
https://docs.google.com/spreadsheets/d/<SPREADSHEET_ID>/edit
```

В приложении на экране **Настройки → Google Sheets** можно вставить как полную ссылку, так и
сам `<SPREADSHEET_ID>` — приложение извлечёт ID автоматически.

## Настройки приложения

Экран **Настройки** (шестерёнка в шапке любой вкладки):

| Карточка | Что настраивается |
|---|---|
| Google-аккаунт | вход/выход (Credential Manager) |
| Google Sheets | таблица выгрузки, «Выгрузить всё», импорт истории при сохранении ссылки |
| Таймер отдыха | отдых по умолчанию (±15 с), автостарт после подхода, звук и вибрация уведомления |
| Интерфейс | виброотклик (тактильная отдача на нажатия по всему приложению) |
| Акцент | цвет интерфейса и иконки лаунчера (4 варианта) |
| Данные | экспорт базы (SQLite-копия через системный диалог), полная очистка истории, версия |

Экспортированный файл — обычная база SQLite; восстановление — замена файла `gym.db` в данных
приложения (или просмотр любым SQLite-инструментом). «Очистить данные» стирает историю,
программы и свои упражнения, но сохраняет настройки и встроенный каталог.

## Сборка и тесты

```bash
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleRelease   # R8 + сжатие ресурсов; подпись настраивается отдельно
```

Графики и карта тела нарисованы вручную в Compose Canvas, поэтому у них есть тест отрисовки
(`AnalysisRenderTest`, Robolectric + нативная графика). Он не сравнивает пиксели с эталоном, но
падает на ошибках рендера и складывает снимки в `app/build/reports/analysis-render/` — их удобно
посмотреть глазами после правок вида.
