# Конструкции для выбора

Эти структуры выделены редакционно из базы. «Зачем» описывает предполагаемый механизм,
а не измеренный рост продаж. Примеры для Yarumo написаны заново и требуют сверки функций.
Бери конструкцию, меняй заход и длину под задачу; не повторяй её дословно из поста в пост.

## Выбор по задаче

| Задача | Конструкции |
|---|---|
| Впервые объяснить ценность | P01, P02, P03 |
| Помочь решиться попробовать | P04, P05, P06 |
| Показать изменения и участие автора | P07, P08 |
| Подкрепить доверие | P09, P10 |
| Вовлечь и вернуть | P11, P12, P13 |
| Сделать серию к запуску | P14 |

## P01. Узнаваемая сцена → конкретное действие → наблюдаемая польза

**Когда:** человек ещё не понимает, зачем отдельное приложение.
**Конструкция:** одна знакомая ситуация → чего в ней не хватает → что сделать в продукте
→ что станет доступно после действия. При необходимости — предложение попробовать.
**Зачем:** польза становится проверяемой, читателю не нужно расшифровывать список функций.
**Опора:** [приложение Максима Соколова](https://t.me/fitness_maxim/325),
[бытовое объяснение Артёма](https://t.me/trener_artem/3117).
**Заход Yarumo:** «В прошлый раз было восемь повторений или десять? Запись прошлой тренировки
даёт более точный ответ, чем воспоминание между подходами».
**Не переносить:** чужие физиологические цифры; выдуманную потерю прогресса из-за отсутствия дневника.

## P02. Одна функция → один мини-сценарий

**Когда:** показать продукт в тексте, подписи к демонстрации или коротком видео.
**Конструкция:** задача → 2–3 нужных действия → видимый результат → граница функции.
**Зачем:** позволяет мысленно попробовать продукт и снижает неопределённость.
**Опора:** [функции с назначением](https://t.me/fitness_maxim/325).
**Заход Yarumo:** «Переставили упражнения в начатой тренировке. Что будет с программой?»
Показать изменение сессии и отдельное сохранение программы.
**Не переносить:** длинный каталог возможностей; несуществующие кнопки; технические детали вместо пользы.

## P03. Содержательный вопрос → прямой ответ → пример

**Когда:** FAQ, объяснение метрики, анонс полезного материала.
**Конструкция:** конкретный вопрос → ответ без удерживания интриги → пример/пояснение
→ ссылка на демонстрацию, если она нужна.
**Зачем:** читатель получает пользу уже в самом посте.
**Опора:** [вопрос до ссылки у FPA](https://t.me/trenerskayaFPA/2139),
[рубрика вопрос/ответ](https://t.me/fitness_maxim/149).
**Заход Yarumo:** «Можно поменять порядок только на сегодня? Да: изменение в начатой сессии
само по себе не переписывает программу».
**Не переносить:** выдуманный «вопрос подписчика»; пустое «Новое видео!»; диагноз вместо объяснения данных.

## P04. Конкретная проба → состав → условия → действие

**Когда:** есть реально доступная бета, пробный период или платный продукт.
**Конструкция:** для кого проба → что человек сможет сделать → что входит и не входит
→ существенные условия → один ясный способ начать.
**Зачем:** делает решение понятным, сохраняя прямоту продажи.
**Опора:** [небольшой продукт #Sekta](https://t.me/sektaschool/4722),
[доступ и условия DDX](https://t.me/ddxfitness_official/6280).
**Пример направления:** предложить участнику с доступом записать одну обычную тренировку
и проверить, удобно ли затем найти её результат. Это задача проверки, не обещание срока результата.
**Не переносить:** цены конкурентов, фиктивное ограничение мест, бесплатность без подтверждения.

## P05. Барьер выбора → честное различие → подходящий следующий шаг

**Когда:** возражения «мне хватает заметок», «уже есть приложение», «не хочу всё настраивать».
**Конструкция:** признать текущий рабочий способ → назвать конкретное различие → показать
его на задаче → дать сравнить или остаться с текущим способом.
**Зачем:** аргументирует смену инструмента без обесценивания опыта читателя.
**Опора:** [помощь с выбором #Sekta](https://t.me/sektaschool/4817);
адаптация к заметкам и таблицам — редакционная гипотеза Yarumo, не готовый кейс источника.
**Заход Yarumo:** «Если заметки вам удобны, это уже рабочий дневник. Yarumo стоит посмотреть,
если вам важно видеть историю тренировок рядом с данными о нагрузке».
**Не переносить:** ложное сравнение «таблицы бесполезны»; придуманный импорт из другого сервиса.

## P06. Две стадии знакомства → два уместных маршрута

**Когда:** в канале одновременно будущие и действующие пользователи.
**Конструкция:** общая новость → что меняется для каждой группы → отдельное действие каждой.
**Зачем:** не заставляет владельца доступа снова регистрироваться, а нового читателя — искать
недоступную функцию. Два маршрута здесь оправданы, но не нужно добавлять ещё пять CTA.
**Опора:** [Физикл после закрытия потока](https://t.me/fiztransform/5287),
[эфир для подписчиков FitStars](https://t.me/FitStars_Media/3153).
**Пример направления:** участнику беты — сценарий проверки; новому читателю — доступная демонстрация.
**Не переносить:** несуществующий лист ожидания, поддержку куратора и иной сервисный формат.

## P07. Настоящий опыт → неудобство → решение → оставшаяся граница

**Когда:** есть реальный опыт команды или пользователя с разрешённым материалом.
**Конструкция:** что проверяли → что заметили → что изменили/решили → что ещё не решено.
**Зачем:** позволяет оценить продукт и компетентность через конкретную работу.
**Опора:** [эксперимент с трекером Физикла](https://t.me/fiztransform/5202).
**Пример направления:** рассказ о том, как проверяли запись подходов во время тренировки,
только если такие наблюдения действительно предоставлены.
**Не переносить:** «вчера в зале заметили» без исходной истории, выдуманные замеры скорости и точности.

## P08. Обновление → кому полезно → что теперь сделать

**Когда:** релиз функции, исправление, рабочая заметка о разработке.
**Конструкция:** доступное изменение → затронутая задача → демонстрация → версия/условие доступа,
если они влияют на действие. Для плана — явно будущее время.
**Зачем:** превращает журнал изменений в понятное пользователю сообщение.
**Опора:** [дайджест обновлений](https://t.me/fiztransform/5210),
[работа над продуктом за кадром](https://t.me/veryomina/5114).
**Заход Yarumo:** «Порядок упражнений можно изменить прямо в начатой тренировке» — только после
проверки наличия функции у адресатов. Далее объяснить, что случится с программой.
**Не переносить:** «улучшили UX», названия внутренних классов, обещания изменения тела после обновления.

## P09. Реальный кейс → процесс → конкретное изменение → ограничения

**Когда:** есть реальная история с проверенными фактами; без неё выбрать другой приём.
**Конструкция:** исходный способ/задача → как использовали продукт → что изменилось
→ что осталось неудобным → кому такой опыт может пригодиться.
**Зачем:** заменяет абстрактное социальное доказательство понятным случаем.
**Опора:** [отзыв FPA](https://t.me/trenerskayaFPA/2087),
[продолжение истории после результата](https://t.me/lindover/1553).
**Пример направления:** стало удобнее находить прошлую тренировку — если это сказал пользователь;
не подменять его слова обещанием прироста силы.
**Не переносить:** чужого клиента, придуманную цитату, согласие на публикацию или гарантированный итог.

## P10. Принцип работы → его причина → проверяемое последствие

**Когда:** нужно объяснить, зачем поле, ограничение или особое поведение функции.
**Конструкция:** наблюдаемое правило → понятная причина → что пользователь может проверить.
**Зачем:** показывает осмысленность решения и снимает конкретный вопрос.
**Опора:** [объяснение параметров приложения](https://t.me/fiztransform/4826).
**Заход Yarumo:** «Программа для двух залов показывает упражнения, доступные в обоих.
Поэтому её можно выполнить в любом из выбранных залов» — сверить условия выбора.
**Не переносить:** заявлять научную валидность алгоритма только потому, что он реализован.

## P11. Опрос → наблюдение → следующий вопрос или действие

**Когда:** исследование аудитории, проверка сценария, продолжение обсуждения.
**Конструкция:** один понятный вопрос с нейтральными вариантами → затем отдельный пост
с реальным результатом и размером выборки → уточнение или продуктовый вывод как гипотеза.
**Зачем:** показывает, что ответы влияют на работу; даёт повод вернуться без искусственной интриги.
**Опора:** [продолжение квиза FitStars](https://t.me/FitStarsClub/6277),
[опрос Yarumo](https://t.me/yarumocoach/12).
**Пример вопроса:** «Что сложнее в дневнике: записать подход сразу или найти запись через неделю?»
**Не переносить:** варианты с унижением; вывод «90% рынка» из нескольких ответов; ложное большинство.

## P12. Полезная навигация → короткий выбор по задаче

**Когда:** закреп, старт канала, дайджест инструкций или изменений.
**Конструкция:** кому поможет подборка → несколько названий-задач с рабочими ссылками
→ одно направление старта, если оно нужно новичку.
**Зачем:** сокращает усилие поиска, делает архив частью продукта.
**Опора:** [библиотека FPA](https://t.me/trenerskayaFPA/2099),
[подборка апдейтов Физикла](https://t.me/fiztransform/5210).
**Пример названий:** «Записать первую тренировку», «Изменить порядок на сегодня»,
«Посмотреть предыдущий результат». Использовать только существующие материалы.
**Не переносить:** фиктивные ссылки; десятки пунктов без приоритета; рекламный хвост к каждому пункту.

## P13. Честный повтор → причина вернуться → актуальная инструкция

**Когда:** материал полезен новичкам или появился новый контекст.
**Конструкция:** зачем возвращаемся к теме → что актуально сейчас → короткий ответ или ссылка.
**Зачем:** повторяет полезное без выдачи старого материала за новость.
**Опора:** [Артём помечает повтор](https://t.me/trener_artem/3095).
**Заход Yarumo:** «Вернёмся к разнице между программой и текущей тренировкой».
**Не переносить:** «вы просили» без запросов, ложную новизну, серию одинаковых продажных напоминаний.

## P14. Серия с разными задачами → реальное предложение

**Когда:** пользователь просит серию к запуску, анонсу или обновлению.
**Конструкция:** узнаваемая задача (P01) → показ решения (P02) → ответ на барьер (P05)
→ условия пробы (P04) → итог реальной обратной связи (P11/P07), когда он появится.
Порядок и число постов меняются под задачу; последний этап нельзя сочинять заранее как состоявшийся.
**Зачем:** последовательно добавляет информацию для решения, а не повышает давление.
**Опора:** редакционная сборка P01–P13, не измеренная воронка конкретного канала.
**Пример направления:** память о весах → запись подхода → кому удобнее отдельный дневник
→ как попробовать при открытом доступе. В каждом посте должна быть собственная польза.
**Не переносить:** обязательную ежедневную частоту, одинаковый финальный вопрос, фальшивый дедлайн.

## Заголовки и призывы

Сначала выбирай полезное содержание, затем заголовок. Для Yarumo подходят вопрос о поведении
функции, узнаваемая сцена, конкретное изменение и честное условие. Заголовок не должен обещать
ответ, которого нет в тексте. Не повторяй одинаковое «Вы тоже…?» в серии.

| Намерение | Как сформулировать следующий шаг | Условие |
|---|---|---|
| Посмотреть | «Посмотрите, как сохраняется порядок упражнений» | Демонстрация реально приложена |
| Попробовать | «Откройте доступ и запишите свою обычную тренировку» | Доступ и инструкция существуют |
| Обсудить | «В какой момент вы обычно записываете подход?» | Ответ полезен исследованию |
| Купить | Прямо назвать продукт, срок, цену и путь оплаты | Все существенные условия подтверждены |
| Сообщить | Закончить ясным фактом | CTA не нужен для этой задачи |

Мягкая продажа — это релевантное и прозрачное предложение. Не прячь платность, не извиняйся
за цену и не смягчай каждое действие цепочкой «если вдруг вам, возможно, захочется».
