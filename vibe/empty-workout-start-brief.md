# Gate R: старт тренировки из пустого списка (#5, этап 05)

Исследование next_workout_fixes_research, 10.09.2026.

- AC-001: в загруженном действительно пустом каталоге программ доступно основное действие
  «Начать без программы», создание программы остаётся вторичным действием.
- AC-002: loading не показывается как empty. Наличие стандартных программ, даже свёрнутых,
  не считается пустым каталогом.
- AC-003: действие переиспользует WorkoutsViewModel.startEmpty / launchStart и штатные
  разрешение уведомлений, service и navigation. Повторный тап не создаёт две тренировки.
- AC-004: новая тренировка не создаёт RoutineEntity или фиктивные подходы. Отказ уведомлений
  не блокирует старт.

Текущий WorkoutsScreen ограничивает StartBar непустым списком. Во ViewModel уже реализованы
startEmpty и single-flight. null routines означает loading; empty определяется по совокупности
стандартных и личных программ. Данные и service не менять без найденной регрессии.

Владелец WorkoutsScreen.kt и ui/workouts/WorkoutsScreenTest.kt; при необходимом покрытии
ui/WorkoutsViewModelTest.kt. Существующие ActiveWorkoutRepositoryTest проверяют null routine
и отсутствие дочерних записей. Небольшой UI fast path без миграций и новых зависимостей;
использовать существующие компоненты, отступы и строки Kotlin, 48dp и semantics.
