# ValerochkaGym — спецификация приложения учёта тренировок

Дата: 2026-07-31. Статус: утверждена по итогам брейншторма.

## 1. Цель

Android-приложение для личного учёта силовых тренировок: создание программ-шаблонов, запись тренировок с таймером отдыха, автоматическая выгрузка результатов в Google Sheets (строка = подход) для последующего анализа и планирование тренировок в Google Calendar.

Пользователь один (владелец приложения). Публикация в Play Store не планируется — сборка ставится напрямую.

## 2. Ключевые решения

| Вопрос | Решение |
|---|---|
| Типы упражнений | Силовые (вес × повторы), на время (длительность), бег (скорость, наклон, длительность) |
| Библиотека упражнений | Встроенная (~60–80 на русском, по группам мышц) + свои упражнения |
| Программы | Шаблон одной тренировки; запускается когда угодно |
| Google-интеграция | Полноценный вход через Google (OAuth), прямые вызовы Sheets API и Calendar API |
| Формат выгрузки | Одна строка = один подход (tidy data) |
| История | Список прошлых тренировок в приложении + «прошлый раз» на экране тренировки; графики — в Sheets |
| Таймер отдыха | Автостарт после отметки подхода, per-упражнение длительность, ±15 сек, фон через foreground service |
| Календарь | Планирование будущей тренировки по программе → событие с напоминанием |
| UI | Русский язык, кг, тёмная тема — вариант C «expressive-абстракт» |
| Стек | Kotlin, Jetpack Compose, Material 3 Expressive, Room, Hilt, WorkManager, DataStore, один модуль |

## 3. Структура приложения

Нижняя навигация, три вкладки:

1. **Тренировки** (главная)
   - Блок «Ближайшие» — запланированные тренировки (из Google Calendar-планирования); тап по наступившей — запуск программы.
   - Список программ-шаблонов (карточки: название, число упражнений, ~длительность). Действия на карточке: запустить, редактировать, запланировать, дублировать, удалить.
   - Кнопки «Начать тренировку» (по выбранной программе) и «Пустая тренировка».
2. **История**
   - Список завершённых тренировок: дата, название, длительность, суммарный объём, статус выгрузки (Ожидает / Выгружено / Ошибка).
   - Тап → детали: все упражнения и подходы, кнопка «Повторить выгрузку» при ошибке.
3. **Настройки**
   - Вход/выход Google-аккаунта.
   - Ссылка/ID таблицы Google Sheets.
   - Отдых по умолчанию (сек), звук и вибрация таймера.
   - Кнопка «Выгрузить всё» (для накопившихся невыгруженных тренировок).

Полноэкранные сценарии поверх вкладок:

- **Редактор программы** — название, список упражнений (из библиотеки), для каждого: порядок (drag), число плановых подходов с целевыми значениями, время отдыха.
- **Библиотека упражнений** — поиск, фильтр по группе мышц; создание своего упражнения (имя, группа мышц, тип).
- **Активная тренировка** — см. раздел 5.
- **Итог тренировки** — длительность, объём, отметки PR; вопрос «Обновить программу?» при изменении состава; запуск выгрузки.

## 4. Дизайн-система (вариант C — «тёмный expressive-абстракт»)

> ⚠️ **Устарело (замещено 2026-08-02).** Раздел описывает исходный дизайн (бирюза + персик, градиенты,
> свечения, асимметричные скругления). Приложение переведено на строгую однотонную систему
> (единственный акцент `#3DDC84`, плоские поверхности, единые скругления, пружинная моторика,
> плавающий навбар). Актуальные правила и «как делать дальше» — в **[docs/design-system.md](../../design-system.md)**.
> Ниже — исторический контекст.

- База: почти чёрный `#101413`, поверхности — тёмно-зелёные градиенты (`#173029` → `#12211E`).
- Акценты: бирюза `#2DD4BF` / светлая бирюза `#5EEAD4` (основные действия, активные элементы), пастельный персик `#FFC4AA` (вторичный акцент).
- Текст: `#EEF7F4` основной, `#5F7370`/`#6B807C` вторичный.
- Абстрактные радиальные светящиеся пятна (бирюза, персик) на фонах экранов.
- Асимметричные скругления карточек в духе M3 Expressive (например `24-24-24-8`), кнопки-пилюли, крупная жирная типографика заголовков.
- Material 3 Expressive-компоненты и motion; выразительные моменты — завершение подхода, PR, конец тренировки.
- Тема только тёмная (v1).

Экран активной тренировки — утверждённый вариант B: фокус на текущем подходе (крупные значения, кнопки ±, большая кнопка «Подход выполнен»), выполненные подходы сворачиваются в строки-пилюли, будущие — неактивные пилюли.

## 5. Активная тренировка

- Запуск: по программе (упражнения и плановые подходы предзаполнены) или пустая (добавление упражнений на ходу).
- Тренировка выполняется в foreground service: уведомление с названием, таймером тренировки и текущим упражнением. Переживает сворачивание и блокировку; после убийства процесса восстанавливается из БД.
- Для каждого упражнения показывается «прошлый раз»: значения соответствующих подходов из последней завершённой тренировки с этим упражнением. Поля нового подхода предзаполняются этими значениями.
- Шаги степперов: вес ±2.5 кг (долгое нажатие ±0.5), повторы ±1, длительность ±15 сек, скорость ±0.5 км/ч, наклон ±0.5%. Тап по значению — ввод с клавиатуры.
- «Подход выполнен» → автостарт таймера отдыха.
- Таймер отдыха: длительность из упражнения программы (иначе из настроек), на экране и в уведомлении живой отсчёт, ±15 сек, «пропустить»; по нулю — звук + вибрация.
- Экран не гаснет (FLAG_KEEP_SCREEN_ON).
- Добавление/удаление подходов и упражнений на ходу.
- «Завершить» → пустые неотмеченные подходы отбрасываются → экран итога. Если тренировка шла по программе и состав/план менялись — предложение «Обновить программу?».
- «Отменить тренировку» (с подтверждением) — удаление без сохранения.

## 6. Модель данных (Room)

Справочник:

- `Exercise`: id, name, muscleGroup (enum: грудь, спина, ноги, плечи, руки, пресс, кардио, всё тело), type (STRENGTH | TIMED | CARDIO), isCustom. Встроенная база сидируется при первом создании БД.

План:

- `Routine`: id, name, note.
- `RoutineExercise`: id, routineId FK, exerciseId FK, position, restSeconds (nullable → default из настроек), plannedSets — список плановых подходов (JSON: целевые вес/повторы/длительность/скорость/наклон по типу).
- `ScheduledWorkout`: id, routineId FK, dateTime, calendarEventId.

Факт:

- `Workout`: id (UUID), routineId FK nullable, name, startedAt, finishedAt nullable, note, uploadStatus (PENDING | UPLOADED | FAILED), uploadError nullable.
- `WorkoutExercise`: id, workoutId FK, exerciseId FK, position.
- `WorkoutSet`: id, workoutExerciseId FK, setIndex, weightKg nullable, reps nullable, durationSec nullable, speedKmh nullable, inclinePct nullable, isCompleted.

Правила:

- «Прошлый раз» = подходы последней завершённой Workout, содержащей это упражнение.
- Объём тренировки = Σ(weightKg × reps) по выполненным силовым подходам.
- PR упражнения = максимальный вес среди выполненных подходов за всю историю; на итоге отмечаются упражнения с новым PR.
- Активная тренировка = Workout с finishedAt IS NULL (максимум одна).

Настройки (DataStore): e-mail аккаунта, spreadsheetId, defaultRestSeconds (по умолчанию 120), soundEnabled, vibrationEnabled.

## 7. Интеграция с Google

**Аутентификация:** Credential Manager (Sign in with Google) + AuthorizationClient со scopes `https://www.googleapis.com/auth/spreadsheets` и `https://www.googleapis.com/auth/calendar.events`. Разовая настройка проекта: OAuth client ID (Android) в Google Cloud Console с SHA-1 debug-ключа — пошаговая инструкция в README.

**Выгрузка в Sheets:**

- Триггер: завершение тренировки → enqueue WorkManager-задачи (constraint NetworkType.CONNECTED, BackoffPolicy.EXPONENTIAL).
- Лист `Workouts` создаётся при первой выгрузке с заголовком.
- Колонки: `workout_id | date | start_time | workout_name | exercise | muscle_group | type | set_index | weight_kg | reps | duration_sec | speed_kmh | incline_pct | volume`.
- Метод: `spreadsheets.values.append` (RAW), все подходы тренировки одним батчем.
- Идемпотентность: перед append читается колонка `workout_id`; если UUID уже есть — строки не дублируются, статус ставится UPLOADED.
- Статусы в Истории; ручной повтор; «Выгрузить всё» в Настройках.

**Календарь (планирование):**

- «Запланировать» на карточке программы → выбор даты/времени → `events.insert` в календарь `primary`: заголовок «Тренировка: {название}», длительность 1 час (фиксированная в v1), напоминание за 30 минут.
- Событие и локальная запись `ScheduledWorkout` создаются вместе; отмена удаляет обе (`events.delete`).
- Действие интерактивное: при ошибке сети/API — сообщение об ошибке, ничего не создаётся.

## 8. Архитектура кода

Один Gradle-модуль `app`, пакеты:

- `ui/` — Compose-экраны + ViewModel (StateFlow), Navigation Compose, тема.
- `domain/` — модели, use-cases (прошлые значения, объём, PR, маппинг в строки Sheets).
- `data/` — Room (entities, DAO, seed), DataStore, Google API-клиенты за интерфейсами репозиториев, WorkManager-воркеры, foreground services (тренировка, таймер).

DI — Hilt. Kotlin, coroutines + Flow. minSdk 36, targetSdk 37.

## 9. Обработка ошибок

- Нет сети при завершении → тренировка в БД, выгрузка отложена (WorkManager), статус «Ожидает».
- Нет входа Google / не задана таблица → тренировки копятся локально «Ожидает», подсказка в Настройках; после настройки — «Выгрузить всё».
- Ошибка Sheets API (отозван доступ, таблица удалена, квота) → статус «Ошибка» + причина + ручной повтор.
- Ошибка Calendar API → немедленное сообщение, ничего не создаётся.
- Убийство процесса во время тренировки → восстановление активной тренировки из БД при следующем запуске.

## 10. Тестирование

- Unit: расчёт объёма и PR, выбор «прошлых значений», маппинг тренировки в строки Sheets, логика таймера (ViewModel), идемпотентность выгрузки (на фейковом репозитории).
- Room DAO (in-memory): запрос «прошлый раз», каскадные удаления, единственность активной тренировки.
- Google API закрыты интерфейсами репозиториев; в тестах — фейки. UI-тесты в v1 не пишем.
- Тесты только для публичных API классов, стиль — как принято в проекте.

## 11. Roadmap

Порядок реализации; каждый этап заканчивается рабочим приложением.

1. **Каркас** — перевод проекта на Kotlin/Compose, дизайн-система (тема C, базовые компоненты), навигация с тремя пустыми вкладками, Hilt, Room, DataStore.
2. **Библиотека упражнений** — entities + seed встроенной базы, экран библиотеки с поиском и фильтром, создание своих упражнений.
3. **Программы** — CRUD шаблонов: список на главной, редактор программы (упражнения, плановые подходы, отдых).
4. **Активная тренировка** — запуск по программе и пустой, экран варианта B, «прошлый раз», предзаполнение, редактирование на ходу, завершение с итогом и «Обновить программу?», восстановление после убийства процесса.
5. **Таймер отдыха и foreground** — foreground service, уведомление с отсчётом, автостарт, звук/вибрация, keep screen on.
6. **История** — список завершённых тренировок, детали, PR-отметки на итоге.
7. **Google вход + выгрузка в Sheets** — OAuth, настройки таблицы, WorkManager-воркер, статусы и повторы, «Выгрузить всё».
8. **Google Calendar** — планирование тренировок, блок «Ближайшие», отмена.
9. **Полировка** — M3 Expressive-motion (завершение подхода, PR, финиш), пустые состояния, краевые случаи.
